# 近音适配思路（未实现）

> 状态：只记录产品思路；当前不实现、不调研、不改变 matcher 行为。

## 问题

中文网络社区大量使用音近/形近替换造梗或指代，例如：

- `豪猫` ↔ `好猫`
- `克劳德大小姐` ↔ `Claude大小姐`
- `谷谷歌歌` ↔ `Gemini`（叠词人格化，不只是严格近音）

纯字面 lex 会漏掉这些变体；全局模糊匹配又会把普通同音词误收，因此需要“候选级、可解释、可回退”的适配，而不是放宽所有词条。

## 初步方向

1. **别名优先**：能明确列举的变体直接写进 entry aliases / matcher terms，不走模糊算法。
2. **候选级近音规则**：只为具体梗记录少量变体，保存 canonical、variant、来源与置信度；不做全库自动近音扩散。
3. **上下文消歧**：`克劳德` 这类名称必须结合 Claude/AI/模型语境；普通“大小姐/克劳德”不触发。
4. **精确负例护栏**：每个近音变体配普通同音词硬负例，验证不会吞掉非梗表达。
5. **可逆治理**：误报时可删除变体或加 forbid_context，不牵动 canonical 主形。

## 暂不做

- 不做全局编辑距离/ phonetic 模糊匹配；
- 不自动生成同音词表；
- 不让近音规则跨家族传播；
- 不把“像/读起来像”当作命中依据。

## 待后续确认

- 变体由操作员手工声明，还是从证据中半自动建议；
- 置信度与上下文门槛如何定义；
- benchmark 如何分别测“ canonical 命中 ”和“近音变体命中”，避免把别名覆盖率混进主分。
