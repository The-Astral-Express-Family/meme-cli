# 梗判定交接（2026-11-22，操作员人工判定 → 下一轮迭代）

本文档记录 2026-11-22 操作员对候选池清单的一次人工判定结果，交给下一个执行梗工作迭代的 agent。
背景：meme-cli 的 surf 命令每轮从 B 站评论区自动发现"候选"（待定的梗词头，存于 `~/.meme/memes.db` 的
candidates 表）。本轮把池里的 84 个待判词头（按证据分层挑出）呈给操作员判定：**16 个确认为真实梗，

梗证据分 = 复读 / 骨架坍缩 / 独立成评三个特征的合成分数。

### 2. 已触发的两个候选全是误判

精彩 c_3348（dv=6）、小时 c_3792（dv=9）当前占着 triggered 队列——泛用形容词和时间单位词。
触发闸门（跨轮数 / 跨视频数 / 梗证据分）对这类词全部失效，迭代时优先治理（黑名单方向，见第三节）。

### 3. 梗证据分对纯应答词失效

是的 c_4322（梗证 2.6，属全池最高档）、来啦 c_4172、来吧 c_5314、哦哦哦 c_3639、"好快/耶"——
纯应答/客套词照样高频复读、照样独立成评，三个特征全部给高分。

### 4. 提取不完整：梗单元比词头大（操作员改述过表述的 7 个）

启动→**XX启动**；一股→**一股X（味）**；纷争→**纷争开始了**；steam→**steam管家**；
bin哥你做人真的可以→**XX你做人真的可以**；骨架`<X>文本`→字面**请输入文本**；
单字"x"+游戏名"异环"→**x环**。
共同模式：词头粒度的 n 元提取把句式/公式层截断了，真实梗的单元经常是"带槽位的句式"或"整句"。

### 5. 骨架通道的假公式

`<X>行了`（dv=11）、`<X>分钟`（dv=8）未被采纳——就是普通语法模式，不是梗公式；
`<X>文本` 的槽位来自两例完全相同的字面文本，槽位是假的。骨架候选需要更严的"真公式"判据。

## 三、硬性约束（操作员明确指示，不得违反）

1. **"白名单"永远不可取**。不得把确认真实梗清单做成白名单参与检测、打分或触发。确认梗的唯一合法用途是
   **评估标定**——作为度量发现质量的标注集（参照 scripts/replay.ts 里现有的 TRUTH 真梗标注集做法，
   可更新为本文档的 16 个）；非梗清单作负例集（测误报率）。
2. 治理噪音至多产出**黑名单**：把确认的泛用词/噪音沉淀进封禁表（`--ban` 沉淀 generic_auto，或配置
   `detect.generic_extra`），例如精彩、小时。黑名单只封"确认不是梗的"，永不反向"强制确认是梗的"。
3. gta6 偏事件性，收录或标定时注明"谨慎采纳"，不与其他梗同等对待。
