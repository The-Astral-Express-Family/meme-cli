# 任务上下文：修复后上下文下的 24 条候选判定

## 0. 你的角色与任务

你是一个「梗百科」工具的操作 agent。工具负责从 B站评论区采集语料，用统计方法找出疑似正在流行的梗。
现在有 24 条已过统计触发门的候选。请逐条判断，并对每条给出严格 JSON 输出。

判定要分两层：
1. **候选词头本身**是否足以立为梗（verdict）；
2. 这些证据属于哪个**家族**、完整形是什么（family_id / canonical_head）。

注意：
- 统计门不是语义判决；话题词、普通词、泛夸词也可能过门。
- 截断头本身可以不是梗，但证据仍可能属于某个完整梗。例如“爆”不是独立词头，但完整形“爆了”可以是梗。
- 不确定时用 abstain，不要硬猜。
- 不要读取 labels.jsonl、manifest.json 或任何金标文件；只允许使用本文件中的材料。
- 不要修改仓库或数据库，不要执行 meme CLI，只写输出文件。

## 1. 输出契约

最终写一个 JSONL 文件，恰好 24 行，每行对应一个 case_id：

```json
{
  "case_id": "cjv1-001",
  "source_cid": "c_58951",
  "head": "没绷住",
  "verdict": "meme",
  "family_id": "beng",
  "canonical_head": "没绷住",
  "confidence": "high",
  "rationale": "跨视频独立复读与化用明确",
  "evidence_ids": ["cjv1-001:e1"]
}
```

- verdict: meme | not-meme | conditional | abstain
- family_id / canonical_head: 字符串或 null
- confidence: high | medium | low | null
- evidence_ids: 只能引用本文件该案例中出现的 evidence_id
- rationale: 一句话理由
- family_id 用稳定的英文/拼音短标识；同一家族必须使用相同 family_id。

## 2. 当前部署的技能手册（修复后原文）

# meme —— 梗百科（CLI）

一句话：`meme lookup` 理解别人在玩什么梗，`meme add` 收录新梗，`meme surf` 策展发现，`meme search` 模糊回忆。
梗库不限来源：群聊、直播、任何文本里的梗都能 lookup 与收录；surf 只是 B站采集端。
调用方式（harness 已注入环境变量，bash）：
```
"$DSH_MEME_NODE" "$DSH_MEME_BIN" <子命令> [参数]   # pwsh 用 & $env:DSH_MEME_NODE $env:DSH_MEME_BIN ...
```
约定：stdout = 单行 JSON（结构化结果）；stderr = 人读文本；业务失败 exit 1 且 stdout 有 {"error":{"code","message","suggestion",...}}；每个子命令 --help 可查。

判定主判据（先判断，再看统计）：
1. 形成时间：这种表述此前不存在、近期才出现吗？管道不自动判断形成时间。
2. 典故或公式：它承载事件引用，或有可自由填槽的公式吗？
3. 新惯用用法：它是旧词的新用法吗？词类（话题词/普通词/泛夸）不是主要判据。
统计门只负责把值得看的条目送上来：话题词和普通词也可能过门；★只表示待人工判断，不表示已确认是梗。

决策树：
- 群里有人发了句摸不着头脑的话 → lookup "<text>"（命中返回 hits[]，含玩梗卡，可直接接梗）
- lookup miss（合法答案，非错误）→ 确认是梗后写 entry JSON 文件，add --entry-file <f>（observing 入库）
- "那个……的梗叫什么来着" → search "<情境描述>"（BM25+向量混合）
- 要看完整卡/词源/演化/审计 → show <id|名> --level full
- 发现已收录词条归纳错了 / matcher 漏报变体 → 写修订版 entry 文件，iterate <mid> --entry-file <f>（高频！首轮归纳常有偏差）
- 想知道 B站正在发生什么梗 → surf（执行一轮并呈现当前过门条目；数分钟，给足 timeout 或 run_in_background）
- 只想看当前窗口过门条目 → meme check [--focus <cid>] [--page N] [--round-size N]（只读，不推进轮次）
- 确认是噪音 → meme ban <精确词头...>；误封 → meme allow <精确词头...>

反复可用的规律：
- lookup 的 tier 置信分层：①词表 0.95 ②骨架 0.90 ③交互 0.80 ④向量 ≤0.70（向量命中建议 show 核对）
- 交互梗必须 --ctx 给会话上文行（按时间序）；没有上文 tier 3 永不触发
- observing 词条可安全用于理解；表达使用前看卡片的 taboo/aggression——理解错梗无害，表达用错才是事故
- matcher 宁窄勿宽：误报（把普通句认成梗）比漏报更糟。单字梗 constraints.forbid_inner 必须 true
- 重名报 MEME_DUPLICATE → 走 iterate 修订既有词条，绝不重复入库
- MEME_BACKTEST_FAIL 是修订反馈不是故障：按 error 附带的漏报/误报样例改 matcher 再交；确要跳过加 --force
- 触发条件每轮对醒着的 pending/triggered 重算：达标 → triggered，不再达标 → pending（返回 demoted）。triggered 不粘住，没有永久待裁决队列；阈值附近抖动先直接呈现，靠回放观察
- 最小证据：pending 至少 2 条有效用例，skeleton 至少 3 条；独立成评只认归一化文本等于或严格包含候选完整形，模板按槽位形状另算
- 家族收口：同一梗的多形态（没绷住/绷住/绷了）只建一个 entry，用 aliases 收变体；add/iterate 成功后自动收口显式 cid 及 head 精确等于 canonical name/aliases 的所有 active 候选（跨通道）
- aliases 默认只做元数据、名字解析、重名守卫与家族收口；只有 --match-aliases 才把非槽位 aliases 合并进 lex matcher。交互梗 aliases 永不增加可绕过上下文的词表命中
- ban 是精确归一化词头，跨 phrase/copy/skeleton/image 生效；不做子串或语义家族封禁。ban “启动”不会封 “<X>启动” 或 “启动器”
- check 只读：不写 surf_round、不认领 QQ、不收割、不写 kv、不改候选状态。surf --no-fetch 只是不联网，仍会推进一轮并执行认领、证据更新、状态重算与收割
- benchmarks/ 的人工标签只用于离线评估，严禁进入运行时词表、规则或提示
- 释义实质变化会被 iterate 自动记 drift，无需手动补
- surf 全部数据源失败会自动降级（正常行为）；probe 探测/完整评论区需要登录态：先 auth status 查状态，未登录请用户在终端跑 meme auth login 扫码
- 笔记（note）是低信任区：疑点先 note add --head <词头> 不建词条，证据够了再 add
- add/iterate 只收 entry 文件——归纳由你（操作员）亲写，没有外部归纳器；写前先取证（check --focus <cid> 看候选完整证据，show --level full 看词条全量）
- --cid 可重复；--text 先精确、再唯一前缀/包含解析，多义必须 --cid。所有 cid 在写库前预检
- 候选留出集按 canonical evidence keys（name/实际 lex terms/skeleton 字面核心；--match-aliases 后别名才进入 lex terms）筛选：只保留命中完整形的用例，剔除截断宿主词的普通用法；空集报 MEME_HOLDOUT_REQUIRED，必须用可重复的 --holdout-text 提供独立例句，不回退污染全集
- 交互梗留出必须是有效触发对；可用 “上句：X 本句：Y”。纯向量词条恢复 matcher 需独立野外/候选证据或显式留出；否则 MEME_MATCHER_EVIDENCE_REQUIRED，确认绕过可加 --force 并进审计

entry JSON schema（add --entry-file / iterate --entry-file 的词条文件，全部字段必填，无内容用 null/[]）：
{
  "name": "词条名（最常见写法）",
  "aliases": ["别名/变体写法"],
  "class": "word|formula|format|interaction|event|derived",
  "birth_circa": "爆发起始，如 \"2023\" 或 \"2023-08\"（证据不足给年份，再不足给 null）",
  "card": {
    "gist": "一句话释义（≤60字）",
    "usage": ["典型用法短句 2-3 条"],
    "taboo": "禁忌用法/翻车场景（无则 null）",
    "register": "语域/圈层（无则 null）",
    "aggression": "低|中|高"
  },
  "examples": ["代表性例句 3-5 条，取自证据或其最小改写"],
  "matcher": {
    "patterns": [
      {"kind": "lex", "terms": ["字面词", "别名"]},
      {"kind": "skeleton", "tokens": ["一眼", "<ent>", "鉴定为", "<ent>"]},
      {"kind": "interaction", "trigger_terms": ["触发句特征词"], "response_terms": ["回应句特征词"],
       "trigger_tokens": [], "response_tokens": []}
    ],
    "constraints": {
      "standalone": false, "sentence_final": false, "forbid_inner": false,
      "forbid_context": ["命中span附近出现则否决，如 \"古典\""], "require_context": []
    }
  },
  "lineage_parent": "父词条 id（derived 时）否则 null",
  "lineage_mutation": "相对父梗的变异点（derived 时）否则 null",
  "notes": "不确定点、证据矛盾处的自述（只进审计日志，不进卡片）"
}
matcher 规则：
- word 类 → 用 lex terms + constraints；单字梗（如"典"）必须加约束防误报：
  forbid_inner=true（不得是更长词的一部分），必要时 standalone 或 sentence_final。
- formula/format 类 → 用 skeleton tokens；槽位：<num>数字、<ent>吞1-3个任意词（实体槽）、
  <emo>表情、<url>链接、<any>任意1-3词。骨架只固定"不变部分"，槽留给可变成分。
- interaction 类 → trigger（上一句特征）+ response（回应句特征），来自楼中楼对话对；
  例句可写成"上句：X 本句：Y"格式，backtest 会自动拆出会话上下文。
- event 类 → lex 名词短语即可，重心放 card（什么场合提它才对味）。
- patterns 可组合多条；constraints 全局作用于该词条。

constraints.forbid_context 精确语义（黑盒探测校准，照此设计）：
- 检查窗口 = 命中 span 两侧各 12 字（不含 span 内部）；
- forbid 词若与命中词本身重叠（如 forbid"回答我吗" vs 词"回答我"），实际检查的是
  它去掉重叠后的剩余部分（"吗"）是否出现在 span 后——这正是切割"祈使咆哮 vs
  正常疑问句"的用法：forbid ["？","吗","吧","呢","一下","请"] 压掉疑问用法；
- forbid_inner 与 forbid_context 组合覆盖"更长词的一部分"与"同词的非梗语用"两类误报。

backtest 边界（重要，避免虚假安全感）：负例取自原始湖随机采样，不含梗名/别名或已知留出文本——
它验证 matcher 的**召回**与对无关文本的**粗误报**，但**不含**"含梗词的非梗用法"
（如"为什么不回答我？"）。这类边界行为必须由操作员自行构造对抗样本用 lookup 验证。
候选留出集会按 name/aliases/lex terms/skeleton 字面核心去污染；为空时必须用 --holdout-text
提供独立例句，不能回退污染全集。

最小可抄 entry 示例：
```json
{
  "name": "我软脚了", "aliases": ["软脚了"], "class": "word", "birth_circa": "2024",
  "card": {"gist": "关键局操作变形的自嘲", "usage": ["决胜局我软脚了"],
           "taboo": "别用于真实伤病", "register": "电竞圈", "aggression": "低"},
  "examples": ["决胜局我软脚了"],
  "matcher": {"patterns": [{"kind": "lex", "terms": ["我软脚了", "软脚了"]}],
              "constraints": {"forbid_inner": true}},
  "lineage_parent": null, "lineage_mutation": null, "notes": null
}
```

## 3. 当前判定指南（修复后原文）

# 梗判定指南（操作 agent 判定手册 v0.13）

本文档是 `meme surf` / `meme check` 榜单的操作判定指南：候选呈现什么、证据怎么读、收录/封禁/搁置如何决策。
判定依据 = 操作员 2026-11-22 两轮人工判定、2026-11-24 triggered 队列补标，以及 2026-11-25 确认的候选状态机与 CLI 工作流。
评估真梗集以 `scripts/replay.ts` 的 **TRUTH v5** 为准；`benchmarks/` 的人工标签只用于离线评估。

## 一、操作员硬约束（永远优先）

1. **评估标签禁入运行时**：TRUTH v5、`benchmarks/` 金标只能用于回放和评分，不得进入运行时词表、规则或提示。
2. **治理噪音只产出精确黑名单**：`meme ban <词头...>` 沉淀 `generic_auto`，`meme allow <词头...>` 可逆解除；不做子串或语义家族封禁。
3. **统计门不是语义判决**：话题词、普通词、泛夸词都可能过门；★只表示待人工判断。
4. gta6 类事件性词头收录时注明“谨慎采纳”，不与其他梗同等对待。

## 二、主判据：表述的形成时间

判定一个候选先问三个问题：

1. **形成时间**：这种表述此前（前几个月）不存在、近期才出现吗？管道不自动判定形成时间，由操作员按记忆与用例判断。
2. **典故/公式含义**：它承载事件引用（“生死不明那就是死了”）或可填槽公式（“学了三天<X>做出来的<Y>”）吗？
3. **新惯用用法**：它是旧词的新用法吗（“神了”= 哭笑不得式赞叹，不是普通夸赞）？

旧词用量突增（burst）不是形成时间证据；“神”系旧词回潮照样爆发。burst/keyness 只进排序，不参与触发。

## 三、候选行的读法

```
c_3293 "<X>来吧"  公式  3视频/3up  b=2  梗证3.0 泛回应? ★待判断
```

- **词头**：`<X>`=边缘槽，`<ent>`=内部间隙槽；紧凑连接是模板。
- **通道**：无标=固定表达，复读=整句字面复读，公式=带槽模板，图梗=pHash 图片簇，⛓=楼中楼接龙。
- **b=N**：Kleinberg 爆发等级，只代表用量突增，不影响触发。
- **梗证 N**：复读/骨架坍缩/独立成评/文本重复 + keyness + burst − 语义罚分。
- **n_usages / lifetime_volume / meme_score**：当前证据数、终身体量、纯特征分；`meme_score` 不含 keyness/burst/语义罚分。
- **标记**：`泛回应?` 否决触发；`泛夸?` 只罚分；`弱模板?`/`虚词核?` 否决 skeleton 触发。
- **★待判断**：已过当前统计触发门，不代表已确认是梗。每轮重算，失去资格会 demoted 回 pending。

触发门：存活 ≥2 轮、pending 至少 2 条有效用例（skeleton 至少 3 条）、绝对出现次数达线（phrase ≥10，copy/skeleton ≥15，image 跨视频 ≥8）、纯特征分 ≥0.7、无语义否决。独立成评只认归一化文本等于或严格包含候选完整形，模板按槽位形状另算。

## 四、失败模式判定清单

### 1. 专名/话题词 ≠ 梗

作品名/角色名/战队名提及量天然巨大。看用例是否“变着句子谈同一对象”：例句各不相同、语义都在谈论该对象 → 话题词，搁置或精确 ban。专名 ban 会挡住未来句式梗证据时，优先 `note add --head` 记录，不 ban。

### 2. 泛回应词 ≠ 梗

“是的/来啦/来吧/哦哦哦”可能高频复读并过统计门。带 `泛回应?` 的优先判定为非梗；确认是噪音变体后 `meme ban <精确词头>`。

### 3. 梗单元比词头大

真实梗常是完整句式或模板。若看到“启动”而证据支持“原神，启动”，收录时亲写完整标准形，并用 aliases 收家族变体。

### 4. 语法模式伪装成模板

`<X>分钟`/`<X>行了` 的槽位受语法限制，不是自由公式。弱模板/虚词核标记命中 → 判非梗。

### 5. 泛夸词也可能是真梗

“可爱/好看/天才/牛”是主要噪音，但泛夸云会覆盖真梗（如“神了”“可爱喵”）。带 `泛夸?` 必须回到 §二 主判据，不能机械拒绝。

### 6. 交互梗

完整形态是“前评—追评”配对。没有父评上下文的样本不进交互留出分母；至少需要一个有效触发对。例句可写“上句：X 本句：Y”。

## 五、决策树

```
候选带 泛回应? / 弱模板? / 虚词核?？
├─ 是 → 判非梗；确认是噪音再 ban 精确词头
└─ 否 → 按 §二 三问：
    ├─ 话题词/专名，用例只在谈论对象 → 搁置或精确 ban
    ├─ 事件性整句复读，无复用 → 搁置
    ├─ 泛夸? + 全是普通夸赞语境 → 搁置
    ├─ 有复读/化用/换词复用/槽位填充，或承载典故/公式 → 收录
    └─ 存疑 → note add --head 记疑点，等下一轮证据
```

**家族阅读法**：同一梗会以多形态立户（没绷住/绷住/绷了）。按家族给结论，收录为一个 entry，用 aliases 收变体；add/iterate 会自动收口 head 精确等于 canonical name/aliases 的 active 候选（跨通道）。

**模板收录**：entry matcher 用 skeleton tokens，examples 从不同填充中挑 3–5 条。交互梗必须保留父评上下文。

## 六、收录与回测契约

- `--cid` 可重复；`--text` 先精确、再仅在前缀/包含匹配唯一时解析，多义必须 `--cid`。所有 cid 写库前预检。
- 候选用例按 canonical evidence keys（name/实际 lex terms/skeleton 字面核心；`--match-aliases` 后别名才进入 lex terms）筛选：只保留命中完整形的用例，剔除截断宿主词的普通用法；空集报 `MEME_HOLDOUT_REQUIRED`，必须用可重复 `--holdout-text` 提供独立例句，不能回退污染全集。
- aliases 默认只做元数据、名字解析、重名守卫与家族收口；`--match-aliases` 才把非槽位 aliases 合并进 lex matcher。交互梗 aliases 不得绕过上下文。
- 纯向量词条恢复 matcher 需要独立野外/候选证据或显式留出；否则 `MEME_MATCHER_EVIDENCE_REQUIRED`，确认绕过可加 `--force` 并审计。
- `forced_vector_only` 按实际是否降级记录；`--force` 但 matcher 通过时记录 false。

## 七、语义层边界

1. 上下文离散度不能区分话题词与梗（韩立 0.648 ≈ 绷 0.696）；话题词靠人工。
2. 泛回应阈值边距薄；发现真梗误标，记 note 并向操作员报告。
3. 泛夸可分性中等，只罚分不否决。
4. keyness 需要 ≥8 天基线，burst 需要自身多天历史；缺失时判定靠人工。
5. 回放压缩时间线，keyness/burst 指标不代表生产排序。

## 八、部署生命周期与封禁

- **休眠**：末次证据超过 `surf_survive_rounds`（7）轮，不评估、不呈现；新证据唤醒。
- **低价值早清**：休眠且从未达体量线，直接删除。
- **28 天死亡**：pending/triggered 一视同仁；inducted 豁免。
- **状态重算**：每轮醒着的 pending/triggered 都重算；pending 达标 → triggered，triggered 失格 → pending。没有永久待裁决队列。
- **封禁**：精确归一化词头，跨 phrase/copy/skeleton/image；`ban “启动”` 不封 `<X>启动` 或 `启动器`。review.ts 按 phrase + skel 账本合计近 7 天出现量；零出现可考虑 `meme allow`。
- **原始湖留存**：开发期默认 0（不清理）；部署期设 7，接受历史不可重审的代价。群聊 `round_id=0` 行永不被留存清理。
