## 0. 你的角色与任务

你是一个「梗百科」工具的操作 agent。这个工具（命令行程序 `meme`）负责发现、收录、检索中文互联网梗。

用统计方法找出"疑似正在流行的梗"作为候选。候选累计够多证据后自动进入待收录队列，
由**你**逐条判定并处置——工具本身不调用任何外部模型，"是不是梗、该怎么收录"完全由你判断。

现在队列里有 24 条候选（第 5、6 节是全部证据）。请对**每一条**给出判定并执行处置：

| 判定 | 含义 | 要做的事 |
| --- | --- | --- |
| 收录 | 是梗，立一个新词条 | 按第 2 节的 entry schema **亲写**词条 JSON 并入库 |
| 归并 | 是梗，但与本批另一条候选属于同一家族 | 不单独立词条，并入该家族的词条（aliases 收变体），并把这条候选收口 |

这项工作的目的是测量"操作 agent 能否独立完成这段工作"，因此：

## 2. 技能手册（工具随包发给操作 agent 的使用说明，原文）

# meme —— 梗百科（CLI）

一句话：`meme lookup` 理解别人在玩什么梗，`meme add` 收录新梗，`meme surf` 策展发现，`meme search` 模糊回忆。
梗库不限来源：群聊、直播、任何文本里的梗都能 lookup 与收录；surf 只是 B站采集端。
调用方式（harness 已注入环境变量，bash）：
```
node D:/tmp-meme/judge/meme-scratch.mjs <子命令> [参数]   # 本环境只用 bash 写法
```
约定：stdout = 单行 JSON（结构化结果）；stderr = 人读文本；业务失败 exit 1 且 stdout 有 {"error":{"code","message","suggestion",...}}；每个子命令 --help 可查。

决策树：
- 群里有人发了句摸不着头脑的话 → lookup "<text>"（命中返回 hits[]，含玩梗卡，可直接接梗）
- lookup miss（合法答案，非错误）→ 确认是梗后写 entry JSON 文件，add --entry-file <f>（observing 入库）
- "那个……的梗叫什么来着" → search "<情境描述>"（BM25+向量混合）
- 要看完整卡/词源/演化/审计 → show <id|名> --level full
- 发现已收录词条归纳错了 / matcher 漏报变体 → 写修订版 entry 文件，iterate <mid> --entry-file <f>（高频！首轮归纳常有偏差）
- 想知道 B站正在发生什么梗 → surf（候选按梗证据分排序，★可add 优先处理；一轮数分钟，给足 timeout 或 run_in_background）

反复可用的规律：
- lookup 的 tier 置信分层：①词表 0.95 ②骨架 0.90 ③交互 0.80 ④向量 ≤0.70（向量命中建议 show 核对）
- 交互梗必须 --ctx 给会话上文行（按时间序）；没有上文 tier 3 永不触发
- observing 词条可安全用于理解；表达使用前看卡片的 taboo/aggression——理解错梗无害，表达用错才是事故
- matcher 宁窄勿宽：误报（把普通句认成梗）比漏报更糟。单字梗 constraints.forbid_inner 必须 true
- 重名报 MEME_DUPLICATE → 走 iterate 修订既有词条，绝不重复入库
- MEME_BACKTEST_FAIL 是修订反馈不是故障：按 error 附带的漏报/误报样例改 matcher 再交；确要跳过加 --force
- 泛用词（"不行/决赛"）允许入榜但梗证分≈0 自动沉底永不触发——不需要手动 reject；--reject 只用于真噪音
- 释义实质变化会被 iterate 自动记 drift，无需手动补
- surf 全部数据源失败会自动降级为存量模式（正常行为）；probe 探测/完整评论区需要登录态：先 auth status 查状态，未登录请用户在终端跑 meme auth login 扫码
- 笔记（note）是低信任区：疑点先 note add --head <词头> 不建词条，证据够了再 add
- add/iterate 只收 entry 文件——归纳由你（操作员）亲写，没有外部归纳器；写前先取证（surf --focus <cid> 看候选完整证据，show --level full 看词条全量），--cid 把候选用例并入 backtest 正例并收口候选

entry JSON schema（add --entry-file / iterate --entry-file 的词条文件，全部字段必填，无内容用 null/[]）：
{
  "name": "词条名（最常见写法）",
  "aliases": ["别名/变体写法"],
  "class": "word|formula|format|interaction|event|derived",
  "birth_circa": "爆发起始，如 \"2023\" 或 \"2023-08\"（证据不足给年份，再不足给 null）",
  "card": {
    "gist": "一句话释义（≤60字）",
    "usage": ["典型用法短句 2-3 条"],
    "taboo": "禁忌用法/翻车场景（无则 null）",
    "register": "语域/圈层（无则 null）",
    "aggression": "低|中|高"
  },
  "examples": ["代表性例句 3-5 条，取自证据或其最小改写"],
  "matcher": {
    "patterns": [
      {"kind": "lex", "terms": ["字面词", "别名"]},
      {"kind": "skeleton", "tokens": ["一眼", "<ent>", "鉴定为", "<ent>"]},
      {"kind": "interaction", "trigger_terms": ["触发句特征词"], "response_terms": ["回应句特征词"],
       "trigger_tokens": [], "response_tokens": []}
    ],
    "constraints": {
      "standalone": false, "sentence_final": false, "forbid_inner": false,
      "forbid_context": ["命中span附近出现则否决，如 \"古典\""], "require_context": []
    }
  },
  "lineage_parent": "父词条 id（derived 时）否则 null",
  "lineage_mutation": "相对父梗的变异点（derived 时）否则 null",
  "notes": "不确定点、证据矛盾处的自述（只进审计日志，不进卡片）"
}
matcher 规则：
- word 类 → 用 lex terms + constraints；单字梗（如"典"）必须加约束防误报：
  forbid_inner=true（不得是更长词的一部分），必要时 standalone 或 sentence_final。
- formula/format 类 → 用 skeleton tokens；槽位：<num>数字、<ent>吞1-3个任意词（实体槽）、
  <emo>表情、<url>链接、<any>任意1-3词。骨架只固定"不变部分"，槽留给可变成分。
- interaction 类 → trigger（上一句特征）+ response（回应句特征），来自楼中楼对话对；
  例句可写成"上句：X 本句：Y"格式，backtest 会自动拆出会话上下文。
- event 类 → lex 名词短语即可，重心放 card（什么场合提它才对味）。
- patterns 可组合多条；constraints 全局作用于该词条。

constraints.forbid_context 精确语义（黑盒探测校准，照此设计）：
- 检查窗口 = 命中 span 两侧各 12 字（不含 span 内部）；
- forbid 词若与命中词本身重叠（如 forbid"回答我吗" vs 词"回答我"），实际检查的是
  它去掉重叠后的剩余部分（"吗"）是否出现在 span 后——这正是切割"祈使咆哮 vs
  正常疑问句"的用法：forbid ["？","吗","吧","呢","一下","请"] 压掉疑问用法；
- forbid_inner 与 forbid_context 组合覆盖"更长词的一部分"与"同词的非梗语用"两类误报。

backtest 边界（重要，避免虚假安全感）：负例取自原始湖随机采样且不含梗名/别名——
它验证 matcher 的**召回**与对无关文本的**粗误报**，但**不含**"含梗词的非梗用法"
（如"为什么不回答我？"）。这类边界行为必须由操作员自行构造对抗样本用 lookup 验证。

最小可抄 entry 示例：
```json
{
  "name": "我软脚了", "aliases": ["软脚了"], "class": "word", "birth_circa": "2024",
  "card": {"gist": "关键局操作变形的自嘲", "usage": ["决胜局我软脚了"],
           "taboo": "别用于真实伤病", "register": "电竞圈", "aggression": "低"},
  "examples": ["决胜局我软脚了"],
  "matcher": {"patterns": [{"kind": "lex", "terms": ["我软脚了", "软脚了"]}],
              "constraints": {"forbid_inner": true}},
  "lineage_parent": null, "lineage_mutation": null, "notes": null
}
```

# 梗判定指南（操作 agent 判定手册 v0.12）

本文档是 surf 榜单的操作判定指南：候选呈现什么、每类证据怎么读、收录/拒绝/ban 的决策树。
判定依据 = 操作员 2026-11-22 两轮人工判定（2026-11-22 上午 17 条真梗校准 + 下午 round 12-14 池审查）
与同日的机制决策（撤时间窗判据、部署生命周期）确立的结论与硬约束。

## 一、操作员硬约束（永远优先）

1. **"白名单"永远不可取**——确认真梗清单只能用于评估标定（scripts/replay.ts 的 TRUTH 集），不得进运行时。
2. **治理噪音只产出黑名单**：`--ban` 沉淀 generic_auto、配置 `detect.generic_extra`；永不反向"强制确认"。
3. gta6 类事件性词头收录时注明"谨慎采纳"，不与其他梗同等对待。

## 二、主判据：表述的形成时间（操作员人工判据）

**词的类别（泛夸/泛用/专名）不是主要判据。判定一个候选先问三个问题：**

1. **形成时间**：这种表述此前（前几个月）不存在、近期才出现吗？管道**不再**自动判定
   形成时间——曾以"8-90 天基线窗口缺席"作库内代理，因一次性判定会让错过窗口的慢热梗
   永久锁死（2026-11-22 操作员决策撤销）。这一问完全由操作员按自己的记忆与用例判断。
2. **典故/公式含义**：它承载一个事件引用（生死不明那就是死了）或一个可填槽的公式
   （学了三天<X>做出来的<Y>）吗？
3. **新惯用用法**：它是旧词的新用法吗（神了 = 哭笑不得式赞叹，不是普通夸赞）？

旧词的用量突增（burst）**不是**形成时间证据——"神"系旧词回潮照样爆发。burst 只进排序，
不参与任何触发判断。

## 三、候选行的读法

```
c_3293 "<X>来吧"  formula公式  3视频/3up  b=2  梗证3.0 泛回应?
```

- **词头**：`<X>`=边缘槽（utterance 开头/紧邻的可变量），`<ent>`=内部间隙槽（一眼<ent>鉴定为 的可变实体）；紧凑连接（无空格）=模板，含空格旧格式也已兼容。
- **通道**：无标=固定表达（词/短语）、复读=整句字面复读、公式=带槽句式模板、图梗=pHash 图片簇、⛓=楼中楼一字接龙拼接。
- **b=N**：Kleinberg 爆发自动机等级（0=基线态 1=爆发 2=强爆发；新词无基线时显示 b=新）——只代表用量突增，不代表新表述（旧词回潮同样爆发），只影响排序。
- **梗证 N**：score v2（复读对/骨架坍缩/独立成评/文本重复 + keyness + burst − 语义罚分）；<0.1 显示"泛用"。
- **标记**：`泛回应?`=与客套词表语义近邻（是的/来啦类变体，触发被否决）；`泛夸?`=与通用夸赞词云近邻（可爱/好看类，排序罚分**不否决**——真梗也可能带，如神了 0.896/可爱喵 0.882，按主判据人工复核）；`弱模板?`=槽填充过于近同（数量词槽）；`虚词核?`=模板字面全是功能词性。
- **★可add**：已过自动触发门，等待收录判断。触发门 = 存活 ≥2 轮 && 体量线（**绝对出现次数**：词类累计 ≥10 次、结构通道 ≥15 次，均不限轮数——同一视频下的反复复读同样是复读指征，次数 ≥ 跨视频数恒成立；2026-11-22 真实湖敏感度实测校准，操作员确认 5 偏低）&& 纯特征分达标 && 无泛回应/弱模板/虚词核否决——无时间窗，慢积累的梗（笑死/硬控类）达到即触发。**跨 up 门已整体取消**（v0.13：单视频/单群复读浪一并放行，纯特征分门与封禁承担噪音）。注意纯次数分不开单容器话术热点（"做出来"50 次/dv=2 类）——榜单上高次数低 dv 的候选按 §二人工判，确认为热点后 `--reject --ban` 沉淀。

## 四、失败模式的判定清单

### 1. 专名/话题词 ≠ 梗（提及量最大假阳性源）

作品名/角色名/战队名（韩立/BLG/饭堂类）提及量天然巨大，那是话题热度不是梗。**判别：看用例是不是"变着句子谈同一对象"**——用例句式各不相同、语义都是"谈论该对象" → 话题词，拒绝。
专名的用例句句不同、纯特征分低，通常过不了触发特征分门；漏网进队列的判定后 `--reject`
（专名**不再 ban**，专名 ban 了会挡住未来的句式梗证据）。

### 2. 泛回应词 ≠ 梗（复读类特征全部失效）

是的/来啦/来吧/哦哦哦类：照样高频复读、照样独立成评。**已由泛回应标记自动压制**（客套词表语义近邻），带 `泛回应?` 标记的直接拒绝；对漏网变体执行 `--ban`（沉淀进客套云，后续变体自动识别）。

### 3. 梗单元比词头大（截断——v0.11 主修项）

真实梗的单元经常是"带槽位的句式"或"整句"（XX启动/一股X味/XX你做人真的可以）。v0.11 抽取层已按完整单元立户（模板/字面复读），**若仍看到截断词头**（如只有"启动"没有"XX启动"；或"家"对"家人们"、"true"对"This is the true music"），说明证据本身只有截断形——收录时亲写完整标准形 entry，槽位由操作员泛化。

### 4. 语法模式伪装成模板（假公式）

`<X>分钟`/`<X>行了`类：已有填充多样性门控（数量词填充坍缩）+ 弱模板标记 + 全虚词核心标记。三类标记命中 → 拒绝。**注意与真公式的区别**：真公式的槽位是语义自由的实体位（一眼X鉴定为Y 的 X/Y 可以填任何东西）；假公式的槽位是语法位（X 只能是数字/时间词）。

### 5. 泛夸词 ≠ 梗，但真梗可能带泛夸标（v0.11.1 新增）

可爱/好看/天才/牛 类高频夸赞词是触发队列的主要噪音源——`泛夸?` 标记把它们压到榜后段。
**但泛夸云会覆盖真梗**：神了 0.896、可爱喵 0.882 与夸赞云的余弦超过阈值（标定见 §六）。
带 `泛夸?` 标记的候选按 §二主判据人工复核，不要机械拒绝。

### 6. 交互梗（第二轮判定新增类别）

你只是怕了 / 这里不送<B> / 不飞<X> / 别人<A>我<B>就很——完整形态是"前评-追评"的配对结构。
管道能立户其中的**固定半句**（copy/词头），配对关系自动化难度高（操作员注明可不管），
收录时亲写完整交互规则进 entry。

## 五、决策树

```
候选带 泛回应? 标记？
├─ 是 → 拒绝（reject）；若为回应词变体 → reject --ban 沉淀
├─ 否 → 按 §二主判据三问：
│   ├─ 专名/作品/战队话题（用例句句谈同一对象）→ 拒绝（不 ban）
│   ├─ 事件性整句复读（一次事件引用，无复用）→ 拒绝
```

## 六、语义层的已知边界（2026-11-22 两轮标定记录）

1. **上下文离散度不能区分话题词与梗**（韩立 0.648 ≈ 绷 0.696）：评论句子的语言差异远大于话题差异，bge 句嵌入基线余弦 ~0.65-0.70。话题词靠人工（见决策树）。
2. **泛回应判据有效但边距薄**：回应词词头向量 vs 客套云 ≥0.93（真梗最高 0.871）。若发现真梗被误标 `泛回应?`，记 note 并向操作员报告。
3. **泛夸判据可分性中等**：可爱 0.866/好看 0.919/牛 0.902 被捕获；真梗 nb 0.837/没绷住 0.760 安全，但神系 0.887-0.896/可爱喵 0.882 被覆盖——故只罚分不否决。

5. keyness 与 burst 在湖回放里测不出（回放湖的时间线压缩后基线窗口为空）——回放的排序差距不代表生产排序。

## 七、部署生命周期（候选与数据的生死，2026-11-22 操作员决策）

候选的休眠与死亡是**部署期行为**，每轮 surf 末尾自动执行；开发期默认不清原始湖。

- **休眠**：末次证据超过 `surf_survive_rounds`（7）轮的候选不评估、不呈现；新证据自动唤醒。
- **低价值早清**：休眠且从未达体量线的候选直接删除——7 轮里连体量线都没碰到。
- **28 天死亡**：末次证据超过 `candidate_death_days`（28 天）的候选删除，**触发待裁决一视同仁**
  （队列只留新鲜工作；词仍在传播会重新触发重新暴露）；inducted 豁免。死亡 = 删除派生行，
  词头重现会重新立户积累，不是永久放逐。
- **原始湖留存**：`surf_retention_rounds`（0 = 不清理，开发期默认）。部署期设 7：每轮删除
  7 轮前的评论/视频/图片。代价 = 更早历史不可重审（B站评论拉不回历史页）；长期态
  （词条/封禁/日聚合/笔记/审计）永不清理。
- **封禁**：永久封禁 + 定期复核。review.ts 尾部列出每个封禁词近 7 天的日聚合出现量：
  零出现 = 词已自然消退（惰性封禁，可 `surf --allow 词` 移除）；有出现 = 仍在持续拦截。
- **群聊行（QQ，v0.13）**：bot 把每条群消息写成 `round_id=0` 的评论行（合成负数
  rpid/oid，群 = 占位视频行），每轮 surf 开局认领进本轮再抽取——surf 运行中
  新写入的行不会被留存清理误删。已收录词条在群聊里的命中与 B站同批进动态区
  （wildRecheck），衰减/复活有了群聊数据源。榜单上带群证据的候选没有独立标记，
  可用 `surf --focus <cid>` 看用例来源（群占位行的 aid 为负数）。
