# 遇到的障碍

1. **归并无专用收口通道**：CONTEXT 第 0 节要求归并候选"并入该家族的词条……并把这条候选收口"，但 `add` 只能带一个 `--cid`，`iterate`/`edit` 都没有 `--cid`，`add --text` 的"同头合流"对别名/变体头的候选（绷住/绷了/死我了/神）实测不生效。最终只能用 `surf --reject`（无 `--ban`）收口这 4 条，审计语义是"跳过"而非"并入"，与判定语义有偏差；归并关系只能靠本报告与本批 aliases 体现。
2. **闸门与宁窄勿宽的冲突（m_0009）**：候选证据整包变成 backtest 正例（`--cid` 无法剔除单条），其中混有 2 条字面"老师说过"引用，导致召回门槛不过。放宽词表去覆盖字面引用会制造真实误报面，故按手册走 `--force`；代价是词条降级 vector-only，失去词表层快通道，检索召回弱于其它词条。
3. **`--reject` 的"可重复"语义**：帮助文本未说明是重复 flag；第一次用空格列表只收口了 1 条。当场从输出发现并补齐，无副作用。
4. 存疑候选无法在队列内附加"等待证据"标记，只能以悬挂笔记（note #4/#5）呼应，机制上可接受。
